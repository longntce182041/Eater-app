# Saving AI Meal Plans to Database

This guide explains how to save AI-generated meal plans to your MongoDB database.

## Overview

The Eater-app now supports saving AI-generated meal plans with:
- ✅ Main meal plan document with metadata
- ✅ Individual meal items with servings and nutrition
- ✅ Complete nutrition tracking (calories, protein, carbs, fat)
- ✅ Support for multi-day plans
- ✅ Transaction support (atomic saves)

## Database Schema

### MealPlan Model

```javascript
{
  userId: ObjectId,           // Reference to User
  nutritionistId: ObjectId,   // Optional: Reference to Nutritionist
  date: Date,                 // Start date of meal plan
  days: Number,               // Number of days (e.g., 1, 7, 30)
  targetCalories: Number,     // Target calories per day
  actualCalories: Number,     // Actual average calories per day
  dietTypes: [String],        // e.g., ['vegetarian', 'balanced']
  healthGoal: String,         // e.g., 'weight_loss', 'muscle_gain'
  status: String,             // 'active', 'completed', 'cancelled'
  aiGenerated: Boolean,       // true if generated by AI
  metadata: Mixed,            // Additional AI pipeline metadata
  createdAt: Date,
  updatedAt: Date
}
```

### MealPlanItem Model

```javascript
{
  mealPlanId: ObjectId,       // Reference to MealPlan
  recipeId: ObjectId,         // Reference to Recipe
  mealType: String,           // 'breakfast', 'lunch', 'dinner', 'snack'
  servings: Number,           // Number of servings (e.g., 1.23)
  calories: Number,           // Total calories for this meal
  protein: Number,            // Protein in grams
  carbohydrates: Number,      // Carbs in grams
  fat: Number,                // Fat in grams
  createdAt: Date,
  updatedAt: Date
}
```

## Method 1: Using the Service Directly

### In Your Backend Code

```javascript
const aiService = require('./src/api/services/ai.services');
const aiClient = require('./src/integrations/ai/aiClient');
const recipeService = require('./src/api/services/recipe.service');

async function saveUserMealPlan(userId) {
  // 1. Analyze user profile
  const profileData = {
    user_id: userId,
    age: 30,
    gender: 'female',
    height_cm: 165,
    weight_kg: 70,
    goal_weight_kg: 65,
    health_goals: 'weight_loss',
    activity_level: 'moderate'
  };
  
  const profileResponse = await aiClient.analyzeUserProfile(profileData);
  
  const body_profile = {
    age: profileResponse.age,
    gender: profileResponse.gender,
    bmi: profileResponse.bmi,
    bmr: profileResponse.health_metrics.bmr,
    tdee: profileResponse.health_metrics.tdee,
    activity_level: profileResponse.activity_level,
  };

  // 2. Fetch recipes from MongoDB
  const recipes = await recipeService.getRecipesForAI({
    dietTypes: ['vegetarian'],
    limit: 20
  });

  // 3. Generate meal plan with AI
  const mealPlanResult = await aiClient.generateMealPlanPipeline({
    user_id: userId,
    body_profile: body_profile,
    diet_types: ['vegetarian'],
    allergies: [],
    disliked_ingredients: [],
    health_goal: 'weight_loss',
    days: 7,
    recipe_database: recipes
  });

  // 4. Save to database
  const savedPlan = await aiService.saveAIMealPlanToDatabase(
    userId,
    mealPlanResult,
    {
      dietTypes: ['vegetarian'],
      healthGoal: 'weight_loss',
      startDate: new Date()
    }
  );

  console.log('Meal plan saved:', savedPlan.mealPlan._id);
  return savedPlan;
}
```

## Features

### Transaction Support
- All saves use MongoDB transactions
- If any part fails, everything rolls back
- Ensures data consistency

### Metadata Tracking
- Pipeline version
- Steps executed
- Candidate recipes used
- Calorie match accuracy
- Generation timestamp

### Flexible Options
- Custom start date
- Diet type preferences
- Health goal tracking
- Status management

## Error Handling

The save function includes comprehensive error handling:

```javascript
try {
  const result = await aiService.saveAIMealPlanToDatabase(userId, mealPlan);
  console.log('Success:', result);
} catch (error) {
  console.error('Failed to save:', error.message);
  // Transaction automatically rolled back
}
```

## Notes

1. **User ID Format**: Must be a valid MongoDB ObjectId
2. **Recipe IDs**: Must exist in your Recipe collection
3. **MongoDB Connection**: Must be established before saving
4. **Transaction Support**: Requires MongoDB replica set (or standalone with transactions enabled)
